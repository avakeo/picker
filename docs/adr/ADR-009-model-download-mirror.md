# ADR-009: モデルファイルの予備の取得先

- 状態: 提案
- 作成日: 2026-11-02
- 関連: `design.md` 第8章・第12章、ADR-001、T4-1、T4-3

## 文脈

画像とテキストの埋め込みモデル（ADR-001 の clip-japanese）は、アプリに同梱しない。初回に、Hugging Face の LINE 公式リポジトリから次の3ファイルをダウンロードする。

| ファイル | 大きさ |
|---|---|
| `onnx/clyp_visual.onnx` | 約 348MB |
| `onnx/clyp_textual.onnx` | 約 442MB |
| `onnx/spiece.model` | 約 0.8MB |

URL にはコミット `77a62f8af977acd73ec2f927fb73fdaeb13af7d1` を入れて版を固定している。各ファイルの SHA-256 はアプリに書き込んであり、一致しないファイルは読み込まない（`crates/ml/src/registry.rs`）。

改ざんへの対策はこの SHA-256 の検証で足りている。残る問題は、取得先が1つしかないことである。

- LINE がリポジトリを削除するか非公開にすると、新しく入れた人が AI 機能を使えなくなる
- Hugging Face が止まっているあいだは、ダウンロードできない

また、Hugging Face の `resolve` の URL は、302 で配信用のホストに転送される。2026-11-02 に確かめたときの転送先は `us.aws.cdn.hf.co` だった。ダウンロードに使う ureq 2 は転送に従う。今のコードは、URL が `https://` で始まることだけを確かめている。`design.md` の「接続先を固定する」に照らすと、転送先のホストをどう扱うかが決まっていない。

## 提案

### 1. 予備の取得先として GitHub Releases を使う

- このリポジトリの GitHub Releases に、モデル用のリリース（例: `model-clip-japanese-77a62f8`）を作り、3ファイルと LICENSE を置く
- アプリは、まず Hugging Face から取得する。接続できないか、HTTP のエラーが返ったときだけ、GitHub Releases から取得する
- どちらから取得しても、同じ SHA-256 で検証する。ハッシュが一致しなければ、取得先にかかわらず読み込まない
- 取得先の URL は、どちらもアプリに書き込んで固定する

clip-japanese のライセンスは Apache-2.0 なので、再配布できる。再配布するときは、LICENSE を一緒に置く。GitHub Releases の1ファイルあたりの上限は 2GB で、最も大きい 442MB のファイルも収まる。

### 2. 転送先のホストを許可する一覧で制限する

- ダウンロードでは転送を自動で追わず、転送先のホストを、許可する一覧と照らし合わせる
- 一覧には、固定した取得先と、その転送先として確認したホストだけを入れる
- 一覧にないホストへの転送は、エラーにする

Hugging Face と GitHub は、転送先のホストを予告なく変えることがある。その場合は一覧の更新が必要になり、更新するまではそこからダウンロードできない。予備の取得先があれば、片方の変更でダウンロードが全部止まることはない。

## 検討した代替案

| 案 | 採らない理由 |
|---|---|
| Hugging Face だけを使う（今のまま） | リポジトリが消えると、取得する手段がなくなる |
| 自前のサーバーや Cloudflare R2 などに置く | 費用と運用の手間がかかる。GitHub Releases で足りる |
| モデルをアプリに同梱する | アプリが約 790MB 大きくなる。`design.md` 第8章の「同梱しない」と矛盾する |
| GitHub Releases だけを使う | 取得先が1つで、今と同じ問題が残る |

## 影響

- 通信の接続先が増える。`design.md` 第12章の「接続先を固定する」は守れるが、固定する接続先の一覧の更新が必要になる
- モデルの版を上げるたびに、GitHub Releases にも同じファイルを置く。T4-3 のリリースの自動化に含める
- ダウンロードのコードに、取得先の切り替えと、転送先の確認を足す。どちらも、通信をまねたテストで確かめる
- 予備の取得先から取得したことを、ログに残す

## 未決事項

- 予備の取得先に切り替える条件（タイムアウトの秒数、どの HTTP のステータスで切り替えるか）
- 転送先のホストの一覧を、アプリに書き込むか、設定ファイルに置くか
