# ADR-005: 要件定義書 v2 の取り込み範囲

- 状態: 提案
- 作成日: 2026-10-27
- 関連文書: `docs/image_management_app_requirements_v2.md`（以下 v2）、`docs/design.md`、`docs/implementation-plan.md`

## 文脈

デザイナー向けに作成した v2 と `design.md` が、対象 OS、中核機能、検索条件の組み方、重複の扱い、性能目標で食い違っている。AGENTS.md の文書の優先順位に v2 は含まれていないため、どちらに従うかを決めないと実装担当が判断できない。

## 決定（提案）

### 1. 正とする文書

`design.md` を正とする。v2 はデザイナーと共有する要件の一覧として残し、`design.md` と食い違う箇所は v2 側を直す。

### 2. 対象 OS

MVP は macOS（Apple Silicon）のまま進め、Windows は M7 で対応する。v2 の「Windows / macOS 同時対応」は採らない。

OS 依存の処理はすでにトレイトの裏に分けているため、Windows 対応で書き足すのは次の箇所に限られる。DB、ジョブキュー、タグ、学習、検索のロジックは共通で使える。

| 箇所 | macOS | Windows | 見込み |
|---|---|---|---|
| 画像デコード | ImageIO | WIC | HEIC は Windows 既定では読めず、Microsoft Store の有料拡張が必要。代替ライブラリには LGPL と特許の問題がある |
| 推論 | Core ML 実行プロバイダ | DirectML 実行プロバイダ | 同じ ONNX モデルを使えるが、速度と出力の一致を再計測する |
| パスとボリューム | `/Volumes` 配下 | ドライブ文字、UNC パス | パスの大文字小文字を区別しないため、同一性判定のテストを追加する |
| UI 表示 | WKWebView | WebView2 | 仮想グリッドのスクロール性能を再計測する |
| その他 | Finder で表示、Developer ID 署名 | エクスプローラーで表示、Windows 向け署名、CI ランナー | 小さい |

作業量は2〜4週間と見積もる。大半は HEIC の扱いと実機での再計測である。この見積もりは実測にもとづくものではない。

### 3. v2 から取り込む機能

| 機能 | v2 の要件 | 取り込み先 |
|---|---|---|
| 色抽出（最大3色）と手動修正 | FR-19〜FR-21 | M1（T1-12） |
| 手動アルバム | FR-30 | M1（T1-13） |
| 12色パレットによる色検索 | FR-22〜FR-24 | M2（T2-8） |
| 自動アルバム（既定の条件、ユーザー定義の条件） | FR-31〜FR-33 | M3（T3-9） |
| 顔認識と人物グループ | FR-25 の人物検索、FR-34〜FR-36 | MVP 後の M8 |

設計の要点は次のとおりとする。詳細は `design.md` の該当節に書く。

- **色抽出**: サムネイルを入力とする処理段階 `color` を追加する。色の決定は自前実装とする（設計原則5）。ユーザーが修正した色は再生成できないデータとして扱い、自動の再計算で上書きしない。
- **アルバム**: アルバムの所属は Asset に付ける。ファイルを移動・改名しても所属が保たれる。自動アルバムは保存した検索条件として実装し、表示のたびに評価する。
- **顔認識**: 顔検出と顔の埋め込みのために、画像-テキスト埋め込みモデルとは別のモデルを追加する。推論境界に顔解析の境界を加える。顔の特徴量は生体情報にあたるため、機能は既定で無効とし、有効化したときだけモデルをダウンロードする。

### 4. 顔認識モデルのライセンス

顔認識のモデルに限り、非商用ライセンスのモデルを候補に含める。作者がこれを了承している。

ただし次の条件を付ける。

- モデルはアプリに同梱せず、ユーザーが顔認識を有効化したときにダウンロードする。
- 有効化の画面と「このアプリについて」の画面に、モデルのライセンスと非商用である旨を表示する。
- アプリ本体のコードは MIT のまま保つ。モデルの推論に必要なライブラリには、MIT と両立するライセンスを求める既存の規則をそのまま適用する。
- 画像-テキスト埋め込みモデルの選定基準（`design.md` 第8.2節「再配布・商用利用が可能なライセンス」）は変えない。

### 5. 採らない v2 の要件

| v2 の要件 | 扱い | 理由 |
|---|---|---|
| 重複のたびにスキップか登録かを確認する（FR-03、5.1節 手順3） | 採らない | `design.md` では、同じ内容のファイルを1つの Asset に複数の Location として自動でまとめる。T1-4 はこの方式で実装済み。10万枚の初回スキャンで確認が大量に出る |
| 10万枚で検索の初期表示5秒以内（NFR-06） | `design.md` 第13章の「5万枚で200ms以内」を優先する | `design.md` の目標のほうが厳しい。確定値は T0-7 で決める |
| ダークモードのみを基本とする（NFR-12） | ライトとダークの両方を作る | `design-brief.md` で両方を依頼済み。主に使うのはダークという位置づけは保つ |

## 未決事項

| 項目 | 影響 | 決める時期 |
|---|---|---|
| 検索条件の組み方（v2 の「カテゴリ内 OR、カテゴリ間 AND」か、`design.md` の自由な AND / OR / NOT か） | T1-11、T2-8、T3-9 | T1-11 の着手前。決まるまでは `design.md` の方式で設計する |
| 12色パレットの具体的な HEX 値と、近い色とみなす距離の閾値 | T2-8 | デザイナーと合意する |
| 既定の自動アルバムの種類 | T3-9 | T3-9 の着手前 |
| 顔認識モデルの選定 | M8 | T8-1 で検証し、ADR-006 に記録する |
| M8 と M5〜M7 の順番 | ロードマップ | MVP 完了時 |
| v2 にあり `design.md` にない要件（除外リスト FR-07、全画面ビューア FR-38〜FR-39、ショートカットの変更 FR-42） | 今回は扱わない | 別の ADR で扱う |

## 影響

- `design.md`: 目標、データモデル、処理段階、検索、アルバム、顔認識、セキュリティ、未決事項を更新する。
- `implementation-plan.md`: T1-12、T1-13、T2-8、T3-9 と M8 を追加する。
- v2: 対象 OS、重複の扱い、中核機能（自然言語検索、類似画像検索、カスタムタグ）、性能目標、テーマを `design.md` に合わせる。
- `design-brief.md`: 色、アルバム、人物の画面の依頼を追加する必要がある。本 ADR の範囲外とし、別途更新する。
