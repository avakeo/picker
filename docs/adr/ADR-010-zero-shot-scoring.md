# ADR-010: ゼロショット自動タグの採点方法

- 状態: 採用（2026-11-05、未決事項はおすすめの案で決定）
- 作成日: 2026-11-03
- 関連: `design.md` 第8.3節、ADR-001、`crates/ml/src/tagger.rs`、`crates/ml/data/zero_shot_tags.json`

## 文脈

今のゼロショット自動タグは、`design.md` 第8.3節のとおりに次の手順で候補を出している。

1. タグごとに英語のプロンプトを3つ作り（`a photo of …` など）、テキスト埋め込みを平均する
2. 画像埋め込みとのコサイン類似度 `sim` を、`sigmoid(12 * (sim - 0.22))` で確率に変換する
3. 確率がタグ別の閾値（全214語とも 0.62）以上なら `suggested` にする

閾値 0.62 は、類似度 0.2608 以上と同じ意味になる。つまり、どの画像にも同じ類似度の基準を当てている。

### 手元の249枚で起きていること

2026-11-02 に、手元のライブラリ（249枚）で次のことを確かめた。正解ラベルはまだないので、正解率は測っていない。以下は、類似度の分布と、7枚の上位タグを目で確かめた結果である。

| 項目 | 値 |
|---|---|
| 候補が0件の画像 | 109枚 |
| 候補が10件以上の画像 | 10枚（最大45件） |
| 画像ごとの「全タグとの類似度の平均」 | 0.049〜0.235 |
| 1枚の画像の中での、タグどうしの類似度の標準偏差 | 平均 0.034 |
| 類似度の平均と候補の件数の相関 | 0.56 |

画像によって類似度の平均が大きく違い、その差は1枚の中でのタグどうしの差より大きい。そのため、固定の基準では、平均が高い画像には関係のないタグ（「虎」「ラーメン」など）まで付き、平均が低い画像には何も付かない。

一方で、1枚の中でのタグの順位は、目で見たかぎりおおむね合っていた。

- 桜の写真の1位・2位は「桜」「春」
- 水族館の写真の上位は「水族館」「泳ぐ」「海」
- 看板の写真の1位は「看板」
- 誤って「虎」「ラーメン」が付いた画像（ID 26）も、上位は「選手」「自撮り」「男性」で、誤ったタグは基準ぎりぎりだった

### プロンプトの言語

ADR-001 で選んだ clip-japanese は、日本語のテキストで学習したモデルである。日本語のプロンプト「{日本語表示名}の写真」でも同じ249枚を採点し、英語と比べた。

| 項目 | 英語（今） | 日本語 |
|---|---|---|
| 1位のタグの z 値の平均 | 3.27 | 3.78 |
| 例: 水族館の写真での「水族館」の類似度 | 0.264 | 0.311 |

z 値は、そのタグの類似度が、同じ画像の全タグの平均から標準偏差いくつ分離れているかを表す。日本語のほうが、正しいと思われるタグが他のタグからはっきり離れる。

## 提案

### 1. プロンプトを日本語にする

- タグごとのプロンプトを、`display_name_ja` を使った日本語の文型で作る
- 文型は「{日本語表示名}の写真」「{日本語表示名}が写っている写真」「{日本語表示名}の画像」の3つとし、テキスト埋め込みを平均する（選んだ理由は「決めたこと」を参照）
- 語彙ファイルの `prompt`（英語）は、アプリでは使わなくなる。正解ラベルで比べ終わるまでは残す

### 2. 画像の中での相対的な値で選ぶ

1枚の画像について、全タグとの類似度の平均 `m` と標準偏差 `s` を求め、タグごとに `z = (sim - m) / s` を計算する。

- `z` がタグ別の閾値以上のタグを、`suggested` にする
- 閾値の初期値は、全タグとも 3.0 とする
- 1枚あたりの候補は最大5件とする。閾値を超えた量（`z` − 閾値）の大きい順に残す

語彙ファイルの `threshold` は、確率ではなく `z` の閾値の意味に変える。タグ別に閾値を変えられる点は、第8.3節と同じである。

手元の249枚での試算は次のとおり。

| 方式 | 候補が0件の画像 | 1枚あたりの候補 |
|---|---|---|
| 今の方式 | 109枚 | 約2.0件（0〜45件） |
| 英語・z ≥ 3.0・最大5件 | 74枚 | 1.08件 |
| 英語・z ≥ 2.5・最大5件 | 12枚 | 2.44件 |
| 日本語（「の写真」のみ）・z ≥ 3.0・最大5件 | 23枚 | 1.93件 |
| 日本語（3文型の平均）・z ≥ 3.0・最大5件（採用） | 20枚 | 2.16件 |
| 日本語・z ≥ 2.5・最大5件 | 0枚 | 3.80件 |

z ≥ 2.5 は候補が増えるぶん、誤りも増えると見込んでいる。初期値は控えめな 3.0 とし、正解ラベルを集めてから調整する。

### 3. 画面に出す確信度

UI は今、確信度を 0〜1 の値として受け取る（`docs/ui-contract.md`）。契約は変えずに、`z` を `sigmoid(2 × (z − 閾値))` で 0〜1 に変換して渡す。閾値ちょうどのタグは 0.5 になり、`design.md` 第8.5節の「判定境界付近」が閾値と一致する。

### 4. 既存の候補の作り直し

- 自動タグの処理のバージョンを上げ、既存の画像の候補を作り直す。埋め込みは作り直さない
- 人が承認・却下したタグは変えない。作り直すのは、まだ判断されていない `zero_shot` の候補だけとする

### 5. 精度の測り方

第8.3節の「評価用の小さなラベル付き画像セットで精度を測って決める」は、そのまま守る。

- 正解のタグごとにフォルダに分けた画像を用意し、`crates/ml/examples/eval_zero_shot.rs` で精度を測る
- アプリで人が承認・却下した結果も、正解として集計に使えるようにする
- 正解ラベルが集まるまでは、この ADR の数値は傾向を示すものとして扱う

## 検討した代替案

| 案 | 採らない理由 |
|---|---|
| 今の方式のまま、タグ別の確率の閾値を調整する | 画像ごとの類似度の底上げの差が、タグ別の閾値では直らない。同じタグでも、平均が高い画像では付きすぎ、低い画像では付かない |
| 英語のまま、画像の中での相対的な値で選ぶ | 候補が0件の画像が74枚残る。日本語のほうが正しいタグが目立つ |
| 1枚あたり上位 k 件を必ず出す | 何も写っていないような画像にも、関係のないタグが必ず付く |
| 英語と日本語のプロンプトを混ぜて平均する | 249枚では試していない。日本語だけで足りなければ、実装のときに比べる |

## 影響

- `design.md` 第8.3節の「英語プロンプト」と「類似度を確率に変換し、閾値を超えたもの」を、この ADR の内容に書き換えた
- 語彙ファイルの `threshold` の意味が変わる。値もすべて置き換える
- 自動タグの処理のバージョンが上がり、既存のライブラリで候補の作り直しが走る。1枚あたりの計算は類似度の計算だけで、埋め込みは使い回す
- 語彙のタグの数を大きく増減すると、`m` と `s` が変わり、同じ閾値でも候補が変わる。語彙を変えたときは、精度を測り直す

## 決めたこと

2026-11-05 に、提案時の未決事項を次のとおり決めた。

| 項目 | 決めた内容 |
|---|---|
| 日本語の文型 | 3文型の平均（下の表の D） |
| `z` から確信度への変換 | `sigmoid(2 × (z − 閾値))` |
| 英語の `prompt` | 正解ラベルで比べ終わるまで残す |
| 閾値の初期値 | 全タグ 3.0。正解ラベルが集まってから調整する |

文型は、手元の249枚で6通りを比べて選んだ。正解ラベルがないので、1位のタグの z 値の平均（正しいタグがどれだけ目立つか）と、候補が0件になる画像の数を目安にした。

| 文型 | 1位の z 値の平均 | z ≥ 3.0 で候補0件 | 1枚あたりの候補 |
|---|---|---|---|
| A: の写真 | 3.78 | 23枚 | 1.92件 |
| B: が写っている写真 | 3.65 | 30枚 | 1.94件 |
| C: の画像 | 3.89 | 15枚 | 2.15件 |
| D: A＋B＋C の平均（採用） | 3.85 | 20枚 | 2.16件 |
| E: A＋B の平均 | 3.76 | 29枚 | 2.02件 |
| F: A＋B＋「を撮った写真」の平均 | 3.73 | 31枚 | 1.93件 |

C と D の差は小さい。`design.md` 第8.3節の「複数の文型を平均する」に合い、1つの文型の癖に左右されにくい D を選んだ。

採用後の実装で、249枚のうち候補が多いタグは「人」45枚、「自撮り」39枚、「友人」23枚だった。

「自撮り」の39枚を目で確かめたところ、自撮りは12枚、判断できないものが7枚、自撮りではないものが20枚だった。人が写った写真なら、ほかの人が撮ったものにも付いていた。確信度が0.9以上の9枚は、8枚が自撮りで、1枚は判断できなかった。そこで、「自撮り」の閾値だけを4.0に上げた。249枚での候補は9枚になり、自撮りではないと利用者が確かめた ID 2、4、20、26 は候補から外れた。この閾値は目視の39枚で決めたので、正解ラベルが集まったら測り直す。
