# ADR-008: 内容が変わったファイルのタグと、欠落したファイルの確定

- 状態: 提案
- 作成日: 2026-10-29
- 関連: `design.md` 第7.2節、T1-4

## 文脈

T1-4 の受け入れ条件は、移動・改名・複製・削除・内容の変更の各場面について、タグの引き継ぎを含めてテストすることを求めている。移動・改名・複製・削除は `design.md` 第7.2節で扱いが決まっており、テスト `identity_scenarios_keep_tags_on_the_same_content` で確かめた。

次の2点は、どの文書にも決まりがない。

1. **内容の変更**: 同じパスのファイルを編集すると、ハッシュが変わるため別の Asset になる。今の実装では、タグは元の Asset に残り、編集後の Asset にはタグがない（テスト `changing_file_content_creates_a_new_asset_and_keeps_the_old_tags_on_the_old_one`）。写真を少し補正しただけでタグが消えたように見える。
2. **欠落の確定**: 第7.2節は、見つからなくなったファイルを「欠落」とし、「一定期間後または次回のフルスキャンで確定する」としている。期間と、確定したときに何を消すかが決まっていない。今の実装は欠落のまま残し続ける。

## 提案

### 1. 内容が変わったファイル

同じルートの同じパスで内容が変わり、元の Asset にほかの present の Location がない場合は、元の Asset の確定・却下のタグ割当と、手動アルバムの所属を新しい Asset に写す。元の Asset はそのまま残す。

- 元の Asset にほかの Location がある場合（複製の片方だけを編集した場合）は写さない。複製と編集後のファイルは別の画像として扱う
- 自動タグ（`suggested`）は写さない。新しい内容から作り直すため

### 2. 欠落の確定

欠落になってから30日たった Location を、スキャンのときに削除する。Asset とタグは消さない。同じ内容のファイルが戻れば、ハッシュで同じ Asset に結び付くため。

- オフラインのルートの Location は対象にしない
- Location が1つもない Asset はグリッドに出さない。タグとアルバムの所属は、エクスポートに含める

## 採用した場合の作業

- `IdentityResolver::sync_root` で、同じパスの Asset が変わったときの写し替え
- 欠落の日時を記録し、30日を過ぎたものを削除する処理
- 上の2つのテスト
