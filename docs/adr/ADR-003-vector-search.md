# ADR-003: ベクトル検索方式

- 状態: 提案
- タスク: T0-5
- 作成日: 2026-09-25
- 計測環境: Apple M5 / 16 GB / macOS 26.6.2 / arm64（計測前提）

## 文脈

埋め込みベクトルをSQLiteと組み合わせて検索する方式を比較する。T0-3の採用決定を待たず、候補モデルの代表的な次元数（512、768、1152）をすべて計測する。比較対象はself full scanとsqlite-vecとし、sqlite-vecを実行できない環境では未計測として記録し、結果を推測で補完しない。

## 計測前に固定した評価基準

以下を計測前コミットで固定する。計測後に重み、足切り条件、データ生成方法を変更しない。変更する場合は別コミットで理由を記録し、変更後の条件で再計測する。

### 比較条件

- 次元数: 512、768、1152
- 件数: 10,000、50,000、100,000
- 表現: f32、f16
- クエリ: 各条件で固定seedから生成した同一クエリ集合
- 実行: cold相当の初回1回を除外し、warm-up後に複数回測定
- 更新: 初期投入、追加、更新、削除、再起動後の検索

### 重み

| 評価項目 | 重み |
|---|---:|
| 検索時間（p95） | 35 |
| f16の検索結果再現率（f32のTop-kとの一致） | 20 |
| メモリ・保存容量 | 15 |
| 初期投入・更新・削除のコスト | 10 |
| Windowsでの利用可能性 | 10 |
| 依存関係・実装複雑度・ライセンス | 10 |

### 足切り条件

- 50,000件で設計目標の検索応答200msを超えた結果は、目標未達として明示する
- f16のTop-10再現率が95%未満の場合、f16を無条件採用しない
- 検索結果の決定性を再起動後も維持できない方式は不採用
- 追加・更新・削除でインデックスを壊す方式は不採用
- Windowsでの配布またはfallback方針を説明できない方式は不採用
- MITと両立しないライセンスの依存は不採用

## 計画

`tools/t0-5/vector_benchmark.rs` は、決定性のあるベクトル生成、f32/f16表現、full scan、SQLite BLOB保存、任意のsqlite-vec拡張ロード、p50/p95、メモリ・保存容量、Top-k一致率を記録する。SQLite拡張が利用できない場合は、`sqlite-vec: unavailable` として実行環境を記録する。
