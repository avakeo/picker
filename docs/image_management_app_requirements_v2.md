# 画像管理アプリ 要件定義書 Ver. 2.0

- 作成日: 2026-10-27
- 用途: FigmaでのUI/UXデザイン制作、および開発担当者による実装（Claude Code利用を想定）
- ステータス: 56項目の方針を確定。実装詳細・性能条件は一部未確定

> 本文では「確定要件」「初期リリースの推奨範囲」「未確定・要検証事項」を区別する。初期リリースの段階分けは提案であり、最終機能要件を取り消すものではない。

## 1. プロジェクト概要

### 1.1 目的

写真、イラスト、スクリーンショット、デザイン参考画像などを一元的に管理し、ファイル名やフォルダを覚えていなくても、画像の特徴から目的の画像を見つけられるようにする。

### 1.2 想定ユーザー

- デザイナー、イラストレーターなど大量の参考画像を扱う人
- 写真やスクリーンショットを大量に保存する人
- フォルダ管理だけでは画像を探しにくい人

### 1.3 基本方針（確定）

| 項目 | 方針 |
| --- | --- |
| 初期OS | Windows / macOS 同時対応 |
| 将来OS | iOS / Android |
| 画像の保存 | 端末内の元画像を参照し、原則複製しない |
| AI解析 | オンデバイス、オフラインで実施 |
| 通信 | 閲覧・検索・タグ編集・AI解析にネット接続不要 |
| 同期 | クラウド保存・端末間同期なし。各端末のライブラリは独立 |
| UI | ダークモード、画像中心のデスクトップUI |
| 規模 | 約10万枚を想定 |
| 検索性能目標 | 解析済み画像の検索結果の初期表示は原則5秒以内 |
| 開発方針 | 基本機能を先に公開し、高度な機能を段階的に追加 |

## 2. 機能要件

### 2.1 画像取り込み・管理

| ID | 要件 |
| --- | --- |
| FR-01 | PCではユーザーが指定したフォルダを監視し、画像を自動検出・登録する。 |
| FR-02 | 手動インポート操作は設けない。将来のモバイル版では許可された写真ライブラリを取り込む。 |
| FR-03 | 重複画像を検出し、スキップまたは取り込みを選べるようにする。 |
| FR-04 | 元画像が移動・削除された場合は参照不可状態を保持・表示する。 |
| FR-05 | 参照不可画像について、監視フォルダ内の自動再検索と手動指定による再リンクを可能にする。 |
| FR-06 | アプリ内の画像削除は管理情報のみ削除し、元画像は削除しない。 |
| FR-07 | 管理対象から削除した画像は除外リストに登録し、自動再取り込みを防ぐ。 |
| FR-08 | JPEG、PNG、WebP、GIF、HEIC、TIFFなど幅広い画像形式を対象とする。個別の表示・解析可否は検証する。 |

### 2.2 AI解析・タグ

| ID | 要件 |
| --- | --- |
| FR-09 | 画像検出後、バックグラウンドで自動解析を開始する。画像は解析完了前から一覧で閲覧できる。 |
| FR-10 | 被写体・人物・色・雰囲気・画風・構図など幅広い特徴を認識対象とする。 |
| FR-11 | 解析結果に基づき画像ごとにAIタグを生成する。 |
| FR-12 | AI生成タグはユーザーが修正・削除できる。 |
| FR-13 | ユーザーは独自のタグを自由に作成できる。 |
| FR-14 | タグ入力は自由入力と既存タグの候補提示に対応する。 |
| FR-15 | 複数画像に対してタグの一括追加・削除ができる。 |
| FR-16 | ユーザーによる手動編集結果をAI再解析で上書きしない。 |
| FR-17 | AI解析に失敗した場合は失敗状態を表示し、ユーザー操作で再解析できる。自動再試行は基本としない。 |
| FR-18 | AI解析の進捗表示・一時停止・再開ができる。端末負荷に合わせて処理速度を自動調整する。 |

### 2.3 色抽出・色検索

| ID | 要件 |
| --- | --- |
| FR-19 | 画像の実際の色からメイン・サブ・アクセントの最大3色を抽出する。存在しない色を無理に割り当てない。 |
| FR-20 | 抽出色のHEX値などを保持・表示する。 |
| FR-21 | 抽出色をユーザーが手動修正できる。 |
| FR-22 | 色検索には固定の12色パレットを使う。自由な色選択や明度・彩度の検索調整は設けない。 |
| FR-23 | 選択したパレット色に近い抽出色を持つ画像を検索する。 |
| FR-24 | 「メインカラーのみ」と「抽出した最大3色のいずれか」を検索対象として切り替えられる。 |

### 2.4 検索・並び替え

| ID | 要件 |
| --- | --- |
| FR-25 | タグ・色・日付・人物などの条件で画像を検索できる。人物検索は人物認識実装後に有効化する。 |
| FR-26 | 同一カテゴリ内の複数条件はORで評価する。 |
| FR-27 | 異なるカテゴリ間の条件はANDで評価する。 |
| FR-28 | 検索結果は画像グリッドで表示する。 |
| FR-29 | 撮影日・追加日・ファイル名・画像サイズなどで並び替えられる。 |

検索例: （建築 OR インテリア）AND 青系 AND 2025年。

### 2.5 アルバム・人物

| ID | 要件 |
| --- | --- |
| FR-30 | 手動アルバムの作成・編集と画像の追加・削除ができる。 |
| FR-31 | 既定の条件による自動アルバムを提供する。 |
| FR-32 | ユーザーが条件を設定する自動アルバムを作成できる。 |
| FR-33 | 自動アルバムの条件は同一カテゴリ内OR・カテゴリ間ANDとする。 |
| FR-34 | 顔を認識し、同一人物と推定した画像をグループ化する。 |
| FR-35 | ユーザーが人物名を手動で登録できる。 |
| FR-36 | 誤認識した人物グループを統合・分離できる。 |

### 2.6 画像閲覧・操作

| ID | 要件 |
| --- | --- |
| FR-37 | PCでは画像をシングルクリックすると右側の詳細パネルに情報を表示する。 |
| FR-38 | ダブルクリックで全画面画像ビューアを開く。 |
| FR-39 | ビューアで前後の画像移動・ズーム・画面に合わせた表示ができる。 |
| FR-40 | 複数画像を選択し、タグやアルバムなどを一括編集できる。 |
| FR-41 | 検索・選択・移動・ズームなどの基本ショートカットを提供する。 |
| FR-42 | ショートカットのキー割り当てをユーザーが変更できる。 |

### 2.7 バックアップ・設定

| ID | 要件 |
| --- | --- |
| FR-43 | 管理情報をユーザー操作でエクスポート・インポートできる。 |
| FR-44 | タグ・人物・アルバム・色・設定・除外リストなどをバックアップ対象とする。 |
| FR-45 | バックアップに画像本体は含めない。復元時に必要なら元画像を再リンクする。 |
| FR-46 | 監視フォルダやその他アプリ設定を管理できる。 |

## 3. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 対応環境 | Windows / macOSに初期対応する。 |
| NFR-02 | 保存 | 元画像と管理情報は端末内に保存する。元画像は原則参照する。 |
| NFR-03 | プライバシー | AI解析のために画像を外部送信しない。 |
| NFR-04 | オフライン | 閲覧・検索・編集・AI解析はオフラインで動作する。 |
| NFR-05 | 規模 | 約10万枚のライブラリを想定する。 |
| NFR-06 | 応答性 | 解析済み画像の検索結果の初期表示を原則5秒以内とする目標を置く。 |
| NFR-07 | 表示 | サムネイルは可視範囲を優先して段階的に読み込む。 |
| NFR-08 | 解析負荷 | AI解析はバックグラウンド実行し、端末負荷に応じて自動調整する。 |
| NFR-09 | 並行操作 | AI解析中も画像閲覧・検索・タグ編集を可能にする。 |
| NFR-10 | 障害対応 | AI解析に失敗しても元画像と既存管理情報は利用できる。 |
| NFR-11 | データ保護 | 手動編集したタグ・色などを再解析で上書きしない。 |
| NFR-12 | UI | ダークモードを基本とする画像中心のUI。 |

性能目標は未検証。推奨ハードウェア、測定対象、データ件数、解析状況などの試験条件を別途定める。

## 4. 画面構成

### 4.1 PCの基本レイアウト

- 左: ナビゲーション（ライブラリ、検索、アルバム、人物、タグ、設定など）
- 中央: 画像グリッド（可視範囲優先で読み込み）
- 右: 選択画像の詳細（プレビュー、タグ、抽出色、メタデータなど）
- 画像未選択時は右パネルを閉じてグリッド領域を広げる設計を推奨
- 全画面ビューアは独立した閲覧状態として提供

### 4.2 画面一覧

| 画面 | 内容 | 初期リリース方針（提案） |
| --- | --- | --- |
| ライブラリ | 一覧・並び替え・複数選択 | 初期 |
| 検索 | タグ・色・日付などの複合検索 | 初期 |
| 画像詳細パネル | プレビュー・色・タグ・画像情報 | 初期 |
| 全画面ビューア | 拡大・前後移動・ズーム | 初期 |
| アルバム | 手動・条件付き自動アルバム | 手動を初期、条件付き自動を段階追加 |
| タグ管理 | 一覧・追加・編集・削除 | 初期 |
| 人物管理 | 顔グループ・名前・統合・分離 | 後続 |
| 解析状況 | 進捗・一時停止・再開 | 初期（パネル統合可） |
| 設定 | 監視フォルダ・ショートカット・バックアップ等 | 初期 |

将来のスマートフォン版は、下部ナビゲーションと独立した画像詳細画面を基本案とする。

## 5. 主要ユーザーフロー

### 5.1 画像の自動登録

1. ユーザーが監視フォルダを指定する。
2. アプリが画像を自動検出する。
3. 重複を検出した場合は通知し、ユーザーがスキップ／登録を選択する。
4. 画像を一覧に表示する（AI解析完了を待たない）。
5. バックグラウンドAI解析でタグ・色などを保存する。
6. 進捗・失敗状態を確認でき、必要なら一時停止・再開・手動再解析する。

### 5.2 画像を探す

1. 検索画面を開く。
2. タグ・色・日付などを選択する。
3. 同一カテゴリ内OR、カテゴリ間ANDで結果を絞り込む。
4. 結果グリッドから画像をシングルクリックし、詳細を見る。
5. ダブルクリックで全画面ビューアを開く。

### 5.3 タグの編集

1. 画像を選択する（複数選択も可能）。
2. 右詳細パネルまたは一括編集UIでタグを追加・修正・削除する。
3. 手動編集結果を保存し、後続のAI再解析でも保護する。

### 5.4 元画像が見つからない場合

1. 画像を参照不可として表示する。
2. 監視フォルダ内で自動再リンクを試みるか、ユーザーがファイルを指定する。
3. 再リンクできない場合はプレースホルダーを維持するか、管理情報を削除する。

### 5.5 バックアップと復元

1. ユーザーが管理情報をエクスポートする。
2. バックアップファイルをインポートする。
3. 元画像の参照先が変わっている場合は再リンクする。
4. タグ・アルバム・色・設定・除外リストなどを復元する。

## 6. 段階的な開発計画（提案）

### Phase 1: 初期リリース

- Windows / macOS
- 監視フォルダからの自動登録、重複検出、元画像参照
- 画像一覧・詳細・ビューア・複数選択
- AIによる被写体タグ生成、最大3色の抽出
- タグ・色を中心とした検索、手動タグ編集
- 手動アルバム、基本タグ管理
- 解析進捗・一時停止・再開、設定、管理情報バックアップ

### Phase 2: 高度な整理機能

- 顔認識・人物グループ化・統合・分離
- 雰囲気・画風・構図など幅広いAI解析
- 条件付き自動アルバムの拡充

### Phase 3: モバイル展開

- iOS / Android
- 許可された写真ライブラリの自動取り込み
- モバイル向け画面構成
- クラウド同期・端末間同期は行わない

| 項目 | 確認・決定すべき内容 |

| AIモデル | 完全オフラインで被写体・画風・雰囲気を認識するモデルの精度・サイズ・対応OS |
| 処理性能 | 約10万枚の登録・検索・更新性能と推奨PCスペック |

| ファイル監視 | フォルダ追加・変更・大量ファイル更新・権限エラー時の動作 |

| バックアップ | 保存形式、バージョン互換性、復元時の重複・競合処理 |

| ショートカット | OS間のキー差異、初期割り当て、競合時の処理 |
| レスポンシブ | PCウィンドウの最小サイズ、各パネルの折りたたみルール |
| リリース範囲 | Phase 1で対応する画像形式やアルバム機能の詳細 |

## 9. 受け入れ確認の例（初期リリース向け・提案）

- 監視フォルダに画像を追加すると、手動インポートなしで一覧に表示される。
- AI解析が未完了でも画像を閲覧できる。
- AI解析で生成されたタグを修正し、再解析しても修正内容が失われない。
- 画像の色抽出結果を確認・修正し、12色パレットで検索できる。
- 画像をシングルクリックすると詳細、ダブルクリックするとビューアが開く。
- 複数画像のタグを一括編集できる。
- アプリ内で画像を削除しても元ファイルが残り、自動再取り込みされない。
- AI解析を一時停止・再開でき、失敗画像は手動で再解析できる。
- 管理情報のエクスポート・インポートができ、元画像本体はバックアップに含まれない。
- ネット接続がなくても、画像閲覧・検索・編集・AI解析が機能する。

## 10. 仕様管理メモ

- **確定済み**: 最終的に目指す機能方針、Windows/macOS同時対応、オンデバイスAI、10万枚想定、検索5秒以内目標、段階的リリース。
- **提案段階**: Phaseごとの詳細な機能配分、画面構成の一部、受け入れ確認項目。
- **未確定**: 技術選定、データ構造、OS別互換性、詳細UI寸法、性能測定条件。
- **次工程**: Figmaの情報設計・ユーザーフロー・ワイヤーフレームを作成し、開発担当者とPhase 1の受け入れ条件を合意する。
