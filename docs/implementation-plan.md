# ローカル画像管理アプリ（仮称） 実装計画

- バージョン: 0.1（ドラフト）
- 作成日: 2026-09-24
- 前提: `design.md` に従う。章番号の参照は設計書のもの。
- 実装担当: Codex

---

## 1. 作業ルール（Codex 向け）

このルールはリポジトリ直下の `AGENTS.md` にも転記すること。

1. **1タスク＝1プルリクエスト。** 本計画のタスク ID をブランチ名と PR タイトルに含める。
2. **受け入れ条件を満たすテストを必ず含める。** 受け入れ条件が計測値の場合は、計測手順と結果を PR 説明に記載する。
3. **設計書と矛盾する実装をしない。** 必要が生じた場合は実装を止め、`docs/adr/` に提案として ADR を書く。
4. **依存を追加する場合は、PR 説明に目的・ライセンス・検討した代替案を書く。** 依存検査（脆弱性とライセンス）を通すこと。MIT と両立しないライセンスの依存は追加しない。
5. **パニックさせない。** 外部入力（画像、EXIF、XMP、ファイルシステム）の処理はすべてエラー型で返す。
6. **unsafe は原則禁止。** OS の API を呼ぶ箇所に限り許可し、安全性の根拠をコメントで説明する。
7. **OS 固有のコードは条件付きコンパイルで隔離し、トレイトの背後に置く**（設計原則7）。
8. **DB スキーマの変更はマイグレーションの追加でのみ行う。** 既存のマイグレーションを書き換えない。
9. **外部由来の文字列（ファイル名、EXIF、タグ名）を UI で HTML として描画しない。**
10. **テスト用画像は自作またはライセンスが明確なものに限り、リポジトリには小さいものだけを置く。** 大きな評価用データはリポジトリ外に置き、取得手順を文書化する。
11. **UI の文字列は日本語を既定とし、翻訳キー経由で扱う。**
12. **フォーマッタ、静的解析（警告はエラー扱い）、テスト、型チェックが CI で通ること。**
13. **UI は `ui-contract.md` に定義されたコマンド・イベント・サムネイル配信だけを使う。** 契約にない情報が必要になったら、先に仕様書の変更を PR で提案する。
14. **M1〜M3 の UI は仮UIである。** 機能確認に必要な最低限の要素だけを置き、配色・装飾・アニメーションなどの見た目の作り込みはしない。本番UIはデザイナーの Figma デザインに基づいて別マイルストーン（MD）で実装する。

## 2. マイルストーン概要

| マイルストーン | 内容 | 完了の定義 |
|---|---|---|
| M0 | 基盤構築と技術検証 | 空アプリが起動し CI が通る。未決事項の ADR が揃う |
| M1 | ライブラリとインデックス | 1万枚のフォルダを登録し、閲覧・手動タグ付け・重複確認ができる |
| M2 | AI タグと検索 | 自動タグ、類似画像検索、自然言語検索ができる |
| M3 | カスタムタグとレビュー | カスタムタグの提案と、承認・却下による学習ができる |
| MD | 本番UIの実装 | Figma デザインに基づく UI に置き換わり、仮UIが削除されている |
| M4 | リリース準備 | 署名・公証済みの v0.1.0 を GitHub Releases で公開 |

M1〜M4（MD を含む）の完了をもって MVP とする。M5 以降は第5章に概要のみ示す。

### 2.1 デザイナーとの並行作業

コア（M0〜M3）とデザイン作業は並行して進める。進め方は次のとおり。

1. M0 の開始時に `design-brief.md` をデザイナーに渡す。
2. T0-6（仮想グリッドの検証）の前に、グリッドのレイアウト方式をデザイナーと合意する。
3. M1〜M3 は仮UIで進める。コマンドとイベントが揃っていくので、デザイナーは仮UIの実際の動きを見ながらデザインを詰められる。
4. デザインが確定し、かつ M3 が完了した時点で MD に着手する。MD は M3 完了前でも、確定した画面から順に着手してよい。

## 3. タスク一覧

### M0：基盤構築と技術検証

**T0-1 リポジトリ初期化**
- 内容: Cargo workspace（設計書 5.2 のクレート構成で空のクレートを作成）、Tauri v2、Svelte 5 + TypeScript。MIT ライセンス、README、`AGENTS.md`、`docs/adr/`、`docs/security/` を用意する。設計書と本計画を `docs/` に置く。
- 受け入れ条件: macOS で空のウィンドウが起動する。クレート間の依存方向が設計書どおりである。

**T0-2 CI 構築**
- 内容: GitHub Actions の macOS ランナーで、フォーマット検査、静的解析、テスト、Rust 依存の脆弱性・ライセンス検査、フロントエンドの型チェックと lint を実行する。
- 受け入れ条件: main へのプルリクエストで全検査が走り、1つでも失敗したらマージできない設定になっている。
- 依存: T0-1

**T0-3 検証：埋め込みモデルの選定**
- 内容: CLIP / SigLIP 系の候補を3つ以上、ONNX Runtime ＋ Core ML 実行プロバイダで動かし、設計書 8.2 の基準で比較する。
- 計測項目: ロード時間、1枚あたりの推論時間、メモリ使用量、モデルサイズ、ライセンス、日本語クエリの検索品質（実写50枚程度に対して日本語クエリ10個程度で上位結果を目視評価）。
- 成果物: ADR-001（比較表と決定理由）。
- 依存: T0-1

**T0-4 検証：HEIC のデコード**
- 内容: macOS の ImageIO を Rust から呼び出し、HEIC・JPEG・PNG・WebP をデコードしてサムネイルを作る方法を検証する。向き補正と sRGB 変換を含む。
- 成果物: ADR-002（呼び出し方式、性能、フォールバック方針）。
- 依存: T0-1

**T0-5 検証：ベクトル検索方式**
- 内容: 自前の全件走査と sqlite-vec を、1万・5万・10万件で比較する（検索時間、メモリ、実装の複雑さ、Windows での利用可能性）。ベクトルは T0-3 で決めた次元数で、精度は32ビット浮動小数と16ビット浮動小数の両方を試す。
- 成果物: ADR-003。
- 依存: T0-3

**T0-6 検証：サムネイル配信と仮想グリッド**
- 内容: カスタムプロトコルによるサムネイル配信と Svelte の仮想グリッドで、1万枚をスクロールしたときのフレームレートとメモリを計測する。レイアウトはデザイナーと合意した方式（メイソンリーまたは均等グリッド）で検証する。未合意の場合は両方を検証する。
- 成果物: ADR-004（UI フレームワークの最終確認とレイアウト方式を含む）。
- 依存: T0-1

**T0-8 UI 契約の基盤**
- 内容: `ui-contract.md` を `docs/` に置く。Rust 側の型定義から TypeScript の型を自動生成する仕組みを導入し、生成物が最新であることを CI で検査する。コマンドとイベントの契約テストの枠組みを用意する。
- 受け入れ条件: Rust 側の型を変更して型生成を忘れると CI が失敗する。サンプルのコマンド1つで契約テストが動く。
- 依存: T0-1、T0-2

**T0-7 非機能要件の確定**
- 内容: T0-3〜T0-6 の計測結果をもとに、設計書第13章と第15章を更新する。
- 依存: T0-3、T0-4、T0-5、T0-6

### M1：ライブラリとインデックス

**T1-1 DB 基盤とスキーマ v1**
- 内容: SQLite（WAL）、マイグレーション機構、Root・Asset・Location・StageState・Job・Setting のテーブルとリポジトリ層。
- 受け入れ条件: 空の DB から最新スキーマへのマイグレーションがテストで検証されている。

**T1-2 ルートの登録と解除**
- 内容: フォルダ選択ダイアログ、登録・解除・有効/無効の切り替え、UI のフォルダツリー。
- 受け入れ条件: 解除したルート配下の Location は削除されるが、Asset に付いた確定タグは他の Location があれば保持される。
- 依存: T1-1

**T1-3 スキャナ**
- 内容: 再帰走査、対応拡張子の判定、隠しファイルの除外、シンボリックリンクを辿らない。見つかったファイルの Location 登録とジョブ投入。
- 受け入れ条件: 入れ子フォルダ、隠しファイル、シンボリックリンク、非対応形式を含むテスト用ディレクトリで期待どおりの結果になる。
- 依存: T1-1

**T1-4 同一性の判定**
- 内容: サイズと更新日時による変更判定、BLAKE3 ハッシュ、同一ハッシュへの Location 紐付け、欠落の扱い（設計書 7.2）。
- 受け入れ条件: 移動、改名、複製、削除、内容の変更の各シナリオについて、タグの引き継ぎを含めてテストで検証されている。
- 依存: T1-3

**T1-5 ジョブキュー**
- 内容: 永続化されたキュー、段階ごとの状態管理、優先度、段階ごとの並列度、再試行、一時停止と再開、バージョン変更時の再処理（設計書 7.4、7.5）。
- 受け入れ条件: 処理途中でプロセスを強制終了し、再起動すると続きから処理される。段階のバージョンを上げると、その段階と下流だけが再処理される。
- 依存: T1-1

**T1-6 画像処理（デコードとサムネイル）**
- 内容: プラットフォーム境界としてのデコーダトレイトと macOS 実装（ADR-002 に従う）、Rust フォールバック、向き補正、2サイズのサムネイル生成とキャッシュ、入力上限（設計書 7.7）。
- 受け入れ条件: 対応4形式と向き情報付き画像のテストが通る。上限を超える画像と壊れた画像でアプリが落ちず、エラーとして記録される。
- 依存: T0-4、T1-5

**T1-7 メタデータ抽出**
- 内容: 寸法、形式、EXIF（撮影日時、機種、GPS の有無と座標）。EXIF の解析失敗は致命的エラーにしない。
- 受け入れ条件: EXIF あり・なし・壊れた EXIF のテストが通る。
- 依存: T1-5

**T1-8 知覚ハッシュと重複検出**
- 内容: dHash の自前実装、完全一致重複（同一 Asset に複数 Location）と近似重複（ハミング距離が閾値以下）の一覧取得。
- 受け入れ条件: 縮小・再圧縮した画像が近似重複として検出され、無関係な画像は検出されないことをテストで確認。
- 依存: T1-6

**T1-9 フォルダ監視と差分スキャン**
- 内容: ファイル変更通知による監視、デバウンス、起動時とルート復帰時の差分スキャン、外部ボリュームのオフライン判定（設計書 7.3）。
- 受け入れ条件: アプリ起動中の追加・削除・移動・改名が反映される。外付けボリュームを外すとオフライン表示になり、再接続で復帰する。
- 依存: T1-4、T1-5

**T1-10 閲覧（仮UI）**
- 内容: 仮想グリッド、サムネイルのカスタムプロトコル配信（アセット ID のみ受け付ける）、詳細パネル、Finder で表示、インデックス進捗の表示、表示中の画像の処理優先度引き上げ。
- 受け入れ条件: 1万枚で T0-7 で確定したスクロール性能を満たす。カスタムプロトコルにパス文字列を渡しても任意ファイルが読めないことをテストで確認。使用するコマンドとイベントが UI 契約仕様書に定義されている。
- 依存: T0-6、T0-8、T1-6

**T1-11 手動タグとフィルタ（コア＋仮UI）**
- 内容: Tag・TagAlias・TagAssignment のテーブル（状態・出どころ・確信度・モデルバージョンの列を含む完全な形で作る）、タグの作成・改名・削除・統合、エイリアス、親子階層、画像への付与と削除（複数選択に対応）、AND / OR / NOT フィルタ、属性フィルタ、重複一覧画面。
- 受け入れ条件: 設計書 6.2 の不変条件がリポジトリ層のテストで保証されている。親タグでのフィルタが子タグを含む。
- 依存: T1-10

**M1 完了確認**: 1万枚程度の実写フォルダを登録し、閲覧・手動タグ付け・フィルタ・重複確認ができる。

### M2：AI タグと検索

**T2-1 モデルレジストリ**
- 内容: モデルのダウンロード、固定した SHA-256 による検証、保存場所の管理、バージョン管理、進捗と失敗の UI、ライセンス情報の保持（設計書 8.6）。
- 受け入れ条件: ハッシュ不一致のファイルが読み込まれないことをテストで確認。ダウンロード中断後に再開または再試行できる。
- 依存: T0-3

**T2-2 Embedder 境界と ONNX 実装**
- 内容: Embedder トレイト（画像とテキスト）、ADR-001 で選んだモデルの前処理と推論、Core ML 実行プロバイダの利用と CPU フォールバック。
- 受け入れ条件: 同じ画像で再現性のあるベクトルが得られる。参照実装（モデル提供元の Python 実装等）の出力と許容誤差内で一致することを、固定の数枚で確認する手順を文書化する。
- 依存: T2-1

**T2-3 埋め込み段階とベクトル検索**
- 内容: インデックスの embedding 段階、ベクトルの保存、ADR-003 の方式による VectorIndex トレイトと実装。
- 受け入れ条件: 5万件で設計書第13章の検索応答目標を満たす。
- 依存: T0-5、T2-2

**T2-4 類似画像検索**
- 内容: 詳細パネルと右クリックメニューから「似た画像を探す」。
- 依存: T2-3

**T2-5 自然言語検索**
- 内容: テキスト埋め込みによる意味検索と、タグ名・エイリアス一致の組み合わせ（設計書 9.2）。
- 受け入れ条件: タグ名が一致する結果が意味検索の結果より上位に来る。
- 依存: T2-3、T1-11

**T2-6 ゼロショット自動タグ**
- 内容: Tagger トレイト、タグ語彙ファイル（初版は実写向け数百語、日英表示名、カテゴリ、タグ別閾値）、プロンプトテンプレート、語彙埋め込みのキャッシュ、auto_tag 段階（設計書 8.3）。評価スクリプト（ラベル付き評価セットに対するタグ別の適合率・再現率を出力）。
- 受け入れ条件: 評価スクリプトが動き、結果を `docs/eval/` に記録している。`rejected` の組み合わせが再提案されない。
- 依存: T2-3、T1-11

**T2-7 自動タグの表示と確認（仮UI）**
- 内容: グリッドと詳細パネルで、出どころ・状態・確信度を区別して表示する。`suggested` のその場での承認・却下。未確認タグでのフィルタ。
- 依存: T2-6

**M2 完了確認**: 自動タグが付き、「海辺の夕日」のような自然言語検索と類似画像検索ができる。

### M3：カスタムタグとレビュー

**T3-1 フィードバックイベントの記録**
- 内容: 承認・却下・手動付与・手動削除・取り消しを FeedbackEvent として記録する。提示時の確信度も保存する。
- 依存: T2-7

**T3-2 カスタムタグ：プロトタイプ方式**
- 内容: カスタムタグの作成、`user` タグからの切り替え、タグ名テキストによる初期提案、正例3枚以上でのプロトタイプ方式スコアリング、custom_suggest 段階（設計書 8.4 段階A）。
- 受け入れ条件: 正例を追加すると候補が更新される。
- 依存: T3-1

**T3-3 カスタムタグ：ロジスティック回帰**
- 内容: L2 正則化付きロジスティック回帰の自前実装、負例の選び方、段階A から段階B への自動切り替え、再学習のトリガ（設計書 8.4 段階B）。
- 受け入れ条件: 合成データで既知の境界を学習できることを単体テストで確認。数万枚規模で再学習と全件スコアリングが目標時間内に終わる。
- 依存: T3-2

**T3-4 レビュー候補の選定**
- 内容: 判定境界付近の候補と高スコア候補を一定割合で混ぜて選ぶ（設計書 8.5）。混合比は設定値にする。
- 受け入れ条件: 選定ロジックの単体テスト。
- 依存: T3-3

**T3-5 レビュー（コア＋仮UI）**
- 内容: タグごとの候補グリッド、外したものだけを却下して残りを一括承認、キーボード操作、取り消し。ゼロショット自動タグにも同じ画面を使えるようにする。
- 受け入れ条件: 1回の確定操作で承認と却下が正しく記録され、再学習が起動する。取り消しで元の状態に戻る。
- 依存: T3-4

**T3-6 エクスポートとインポート**
- 内容: 再生成不可能データ（設計書 6.3）を JSON で書き出し・読み込み。画像は BLAKE3 ハッシュで参照する。DB の定期スナップショット。
- 受け入れ条件: 書き出したデータを空のライブラリに読み込み、同じ画像を登録するとタグが復元される。
- 依存: T3-1

**T3-7 XMP サイドカー**
- 内容: 確定タグの書き出し、既存 XMP とのマージ（他ソフトの項目を保持）、XML の外部実体と DTD の無効化、既定は無効（設計書 11.3）。
- 受け入れ条件: 既存 XMP の他の項目が保持されることをテストで確認。外部実体を含む XMP を読んでも外部参照が発生しない。
- 依存: T3-1

**T3-8 設定（コア＋仮UI）**
- 内容: モデルの管理、XMP サイドカーの有効化、並列度、バッテリー時の動作、キャッシュの削除と再生成、レビュー候補の混合比。
- 依存: T3-5、T3-7

**M3 完了確認**: カスタムタグを作り、3枚付けると候補が出て、レビューを繰り返すと提案が改善する。

### MD：本番UIの実装

開始条件: 該当画面の Figma デザインが確定していること。仮UIの画面を1つずつ本番UIに置き換える。コア側のコードは変更しない（必要な場合は先に UI 契約仕様書の変更を提案する）。

**TD-1 デザイントークンの導入**
- 内容: Figma で定義された色・余白・文字サイズ・角丸・影などを CSS 変数として実装する。ライトとダークの両テーマ。
- 受け入れ条件: 本番UIのスタイルがトークン以外の固定値を使っていないことを lint または目視チェックリストで確認。

**TD-2 共通コンポーネント**
- 内容: ボタン、入力、タグチップ（出どころと状態の表現を含む）、メニュー、ダイアログ、トースト、進捗表示、空状態、エラー表示などを Figma のコンポーネントに対応させて実装する。
- 依存: TD-1

**TD-3 画面の置き換え**
- 内容: `design-brief.md` の画面一覧に沿って、メイン画面（サイドバー・グリッド・詳細パネル）、タグ管理、レビュー、重複一覧、設定、初回起動とモデルのダウンロード、フォルダ登録の各画面を置き換える。画面ごとに1PR。
- 受け入れ条件: 各画面について、依頼書に列挙した状態（読み込み中、空、オフライン、エラーなど）がすべて表示できる。T0-7 のスクロール性能を維持している。
- 依存: TD-2

**TD-4 操作性の確認**
- 内容: キーボード操作、フォーカス表示、ダークモード、最小ウィンドウサイズでの表示崩れ、スクリーンリーダーでの基本的な読み上げを確認する。
- 依存: TD-3

**TD-5 仮UIの削除**
- 内容: 仮UIのコードと、それだけが使っていた依存を削除する。
- 受け入れ条件: 仮UIへの参照が残っていない。契約テストがすべて通る。
- 依存: TD-4

### M4：リリース準備

**T4-1 セキュリティ強化**
- 開始条件: MD 完了（本番UIに対して点検するため）。
- 内容: Tauri の権限設定の最小化、厳格な CSP、外部由来文字列の描画経路の点検、入力上限のテスト、`docs/security/threat-model.md` の作成（設計書第12章）。
- 受け入れ条件: 脅威モデルの各対策に対応するテストまたは確認手順が文書化されている。

**T4-2 ライセンスと SBOM**
- 内容: 依存ライブラリとモデルのライセンス一覧の生成、アプリ内「このアプリについて」画面での表示、SBOM の生成。
- 依存: T2-1

**T4-3 署名・公証とリリース自動化**
- 内容: Developer ID 署名、公証、GitHub Releases への公開、成果物の SHA-256 と SBOM の添付を CI で自動化する。
- 受け入れ条件: 別の Mac でダウンロードしたアプリが警告なしで起動する。

**T4-4 ドキュメントと v0.1.0 公開**
- 内容: README（スクリーンショット、機能、設計判断へのリンク、プライバシー方針）、ビルド手順、既知の制限。
- 受け入れ条件: v0.1.0 が GitHub Releases に公開されている。

## 4. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| ゼロショット自動タグの精度不足 | 自動タグの有用性が下がる | 語彙とプロンプトの調整、タグ別閾値、評価セットで継続計測。カスタムタグで補う |
| 日本語検索の品質不足 | 自然言語検索が使いにくい | 多言語モデルの優先採用。英語専用の場合はタグ名辞書による変換 |
| HEIC デコードの実装難度 | M1 の遅延 | T0-4 で早期に検証。最悪の場合は OS のコマンドラインツール経由の変換を暫定策とする |
| 大規模ライブラリでの性能 | 起動やスクロールが重くなる | M0 で計測し目標を確定。表示中の画像を優先処理 |
| モデルのライセンス | 配布できない | ADR-001 で確認し、ライセンス情報をレジストリで管理 |
| 実装が設計から逸脱する | 手戻り | 1タスク1PR、受け入れ条件の明確化、ADR による変更管理 |
| デザインが技術的制約と合わない | MD での手戻り | デザイン依頼書で制約を事前共有。グリッド方式は T0-6 前に合意。仮UIの動きを見ながらデザインを詰めてもらう |
| デザインの完成が遅れる | リリースの遅延 | コアは仮UIで先行。MD は確定した画面から順に着手 |
| デザインが契約にない情報を必要とする | コアの追加改修 | 契約の変更を PR で提案し、コア側を先に対応してから UI を実装 |

## 5. MVP 後のロードマップ（概要）

**M5：OCR と判断モデル**
- OCR のプラットフォーム境界と macOS 実装、OCR テキストの全文検索。
- Decider 境界（Jev 互換、choice / score / noul）とローカル Laya（ONNX）の実装。モデルごとの補正設定（温度、`noul` のラベル上書き、位置バイアス対策）。
- タグ・EXIF・OCR テキストから状態記述を組み立て、スマートフォルダ振り分けや保存優先度の判定に使う。

**M6：イラスト対応**
- 写真とイラストの判別。
- Danbooru 系タガーを追加の Tagger として導入し、`danbooru` 名前空間でタグ付け。
- レーティング出力によるサムネイルの自動ぼかし。

**M7：Windows 対応**
- DirectML 実行プロバイダ、Windows の画像デコード基盤によるデコーダ実装、Windows 標準 OCR、パス表記の差異への対応、Windows 向けの署名。

**その他の候補**
- Finder タグとの同期、自動アップデート、Apple Vision による追加 Tagger、Mac App Store 配布の検討。
